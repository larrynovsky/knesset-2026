# Выборы в Кнессет 2026: чтение партий по делам

Слова ничего не стоят — судят только дела. Дело здесь — голосование фракции по законам. Каждый закон помечен как усиливающий или ослабляющий одну из четырёх осей: независимость ветвей власти, свобода экономической деятельности, религия в государстве, безопасность. По этим знакам видно, куда фракция двигалась от Кнессета к Кнессету (20-й → 25-й) и держится ли линия независимо от того, в коалиции она или в оппозиции.

Это не рейтинг и не агитация. Суммарного балла нет и не будет (норма §13 в `CLAUDE.md`): сайт показывает, как голосовали, вывод делает читатель.

## Рамка и авторство

- Темы и оси выбраны автором, а не выведены из данных. Другой выбор осей дал бы другую картину.
- Автор — Александр Ларьяновский. Проект сделан на личные средства (около 200 € на вызовы моделей), без внешнего финансирования и без заказчиков.
- Строили человек, не пишущий код, и LLM-агенты: Claude (Anthropic) писал код, тексты и карточки; Codex (OpenAI) был независимым проверяющим и пересчитывал результаты по сырым данным; Gemini (Google) — третьим читателем в пилоте разметки. Решения о методе, осях и спорных случаях принимал человек.
- Первая итерация намеренно выбирает охват, а не точность: сначала все партии по тем данным, что есть.

Адреса сайта в репозитории нет намеренно (§16): сайт открыт по ссылке и не индексируется.

## Как собрать

Данные в git не входят (сотни мегабайт). Голосования выгружаются из открытых данных Кнессета (`knesset.gov.il/OdataV4/ParliamentInfo`), бюджет — из BudgetKey; скрипты выгрузки — в `scripts/`. `make report` собирает сайт в `site/` и по дороге гоняет самопроверки; `make reproduce` проверяет, что две сборки из одних входов совпадают побайтно. Чего эта проверка не доказывает — в §14.

## История репозитория

Перед публикацией 20.10.2026 история переписана: заменён email автора; удалены рабочие файлы агентов из `reviews/` (оставлены только файлы, которые читает сборка); адреса инфраструктуры заменены метками. Число, порядок и даты коммитов сохранены, проверка «критерии раньше данных» (`scripts/check_criteria_order.py`) после переписывания зелёная. Старые хеши, которые встречаются в документах, переводятся в новые по `docs/reference/commit_map_2026-10-20.tsv`.

Даты коммитов в git ставит автор. Со стороны заверена только дата публикации репозитория.
