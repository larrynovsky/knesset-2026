# crosscheck_owner_laws — контракт и одноразовость

Назначение: независимая от рендерера проверка четырёх законов владельца в make report.
Потребность явная: task_build_v74.md, KNS-L009. Лестница ponytail: ступень 1 —
нужно; ступень 2 — хватает stdlib. Новых зависимостей нет (ступень 4).

Discovery по данным: votes_25, named_votes_cache, by_faction, data-ballot-list,
data-short-law, owner_marks. Найдены reviews/crosscheck_v68.py,
reviews/owner_laws_recount_v43.py и рендер owner_law_positions. Перенесены
парсер HTML, проверка сырых записей и интервальный пересчёт v68; импорт
рендерера запрещён, поскольку проверка должна иметь отдельный путь вычисления.
`python3 -m project_context capabilities votes_25` и
`python3 -m project_context disposability scripts/crosscheck_owner_laws.py`
завершились `No module named project_context`. Это не доказательство отсутствия
дублей; поиск выполнен непосредственно по файлам и ключам данных.

Входы (только чтение): criteria/ballot_2026.json, owner_marks_2026-10-10.yaml;
data/votes_25.json, KNS_PersonToPosition_54.json, KNS_Faction.json,
named_votes_cache/<vote_id>.json; site/cheatsheet.html, l-1…14.html.
CLI: --root меняет корень входов, --site меняет только каталог HTML;
--selftest работает на автономных HTML-копиях в памяти, без сайта и данных.
Выход: stdout/stderr и exit 0/1; запись файлов отсутствует.

Выбор стадии: последнее третье чтение в снимке, иначе последняя передача
для подготовки первого чтения. Голоса пересчитываются из кешей по MkId,
проверяются длина, уникальность, VoteID и допустимые ответы. Значения
счётчиков by_faction не используются. Ключи by_faction дня используются
для разрешения фракционной принадлежности и статуса «фракции не было» (v71).
Состав N ограничен участниками дня снизу и всеми членами каденции сверху.
Позиция определима, только если одна и та же для всех допустимых N.
Участие >=1/3, затем строгое большинство за/против; для Яшар — два человека,
распознаваемые по еврейским фамилиям с проверкой имён, как в v68.
Отсутствие позиции не заменяется выдуманным направлением.

Проверяются основные позиции 56 клеток шпаргалки, 60 клеток
фракций/личных голосов на l-страницах. У нового списка l-12 нет клеток;
обязателен текст «голосов нет». Пояснения в скобках и числовые подсказки
не сверяются. Пропавшие/лишние строки и клетки, неверные входы — отказ.
Неопределимость считается по уникальной паре список × закон, не по копиям
на страницах. <=5 допустимо и печатается; >5 — отказ. Определимые фракции
l-страниц проверяются даже при неопределимой второй фракции того же списка.

Оракул: --selftest требует чистый HTML зелёным, поочерёдно подменяет
«за» на «против» в копии каждой из 15 страниц и требует отказа; проверяет
удаление клеток, границу 5/6, границу участия и повреждённый сырой кеш.
Обычный CLI проверен также на копиях текущего site с подменой и exit 1.

Границы: условная атрибуция по ключам дня, не независимый исторический
реестр; неизвестные точные N и тождество MkId/PersonID остаются допущениями
v68. Пять прежних неопределимых клеток v68 определяются правилом v71,
что не делает вывод об отсутствии фракции независимым от этих ключей.
Оракул не проверяет читательское понимание или полноту выгрузки сервера.

Вердикт одноразовости: ДА. Самостоятельный read-only CLI без собственного
состояния; заменяется другим пересчётом с тем же exit-контрактом. Удаление
требует убрать его вызовы из Makefile; потеряется независимый сборочный
контроль, но данные и рендеры не зависят от реализации.
