# arrow_robustness — контракт и одноразовость

Назначение: требуемый владельцем сценарный расчёт сохранения стрелок при ошибках знаков.
Поиск повторного использования: bill_id, up_bills, down_bills, compose, arrow_of,
flip, robustness в scripts/. Расчёт стрелок переиспользован; симулятор не найден.
`python3 -m project_context capabilities bill_id` и `disposability scripts/arrow_robustness.py`:
модуль project_context не установлен. Отсутствие выдачи не доказывает отсутствие дубля.

Вход: votes_25.json; direction_arrow_2026-10-07.json; решающие знаки Claude;
три theme_signs; правила sign_table/arrow_rule/_arrow_split из существующего конвейера.
Единица ошибки: bill_id со знаком ±1 и хотя бы одним голосованием в снимке.
В каждом прогоне ровно round-half-up(p*N) различных законов; один переворот для всех
чтений/фракций. Нули неизменны. Нет стрелки — null, не 100% устойчивости.
2000 прогонов для каждой темы и p; seed=35; сортировка population перед sample.
Выход: data/arrow_robustness.json, reviews/arrow_robustness_v35.md; UTF-8.
JSON: topics → theme → factions → faction ID → arrow/up/down/retained/rates/label.
Ошибки чтения/разбора входов останавливают расчёт. Исключения не подавляются.

Оракул: --selftest проверяет 100:0, 50:50, 67:33, границы ярлыков и убивает
мутацию отключения flip. Равные доли 50:50 проверены на N=4 (2:2, ненадёжна)
и N=100 (50:50, устойчива). Число законов существенно; оно явно названо в review.

Вердикт одноразовости: ДА, модуль заменяем. Формат JSON — единственная граница
с рендером; симулятор не владеет голосами/знаками, не изменяет первичные входы,
не имеет состояния и сетевых эффектов. Его можно заменить, сохранив контракт.
Удаление функции отображения и двух строк Makefile снимает интеграцию.

Ponytail: потребность явно заказана; stdlib random/json достаточно;
существующие compose/arrow_of и загрузчики использованы; новых зависимостей нет.

Кэш v46: inputs_sha — SHA-256 имён и байтов голосов, direction_arrow, всех
theme_signs/claude_tiebreak_signs/axis_second_reading, YAML порогов, таблиц
for_option_sign и исходников расчёта/загрузчиков; RUNS, SEED, PS входят явно.
Совпадение пропускает build; отсутствие/старый/повреждённый JSON пересчитывается.
JSON заменяется атомарно; изменение входов во время расчёта вызывает отказ.
Параллельные холодные запуски могут считать одновременно; блокировки нет.
make robustness вызывает расчёт с кэшем; report зависит от robustness.
--selftest проверяет однобайтовую мутацию каждого семейства входов, параметры,
добавление/удаление файла и запрет build при совпавшем inputs_sha.
