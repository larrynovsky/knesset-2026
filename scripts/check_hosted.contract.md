# check_hosted — контракт и одноразовость

Назначение: внешняя проверка выложенного сайта на Hetzner (pull): файлы site/ == ответы сервера по sha256,
noindex заголовком и мета, HSTS, robots без Disallow, служебные пути — 404.
Поиск повторного использования (по данным): кто читает site/ и ходит по HTTP — `grep urlopen|requests` в scripts/
среди читателей site/ — нет. check_report_canon читает site/ локально, сеть не трогает.
`project_context capabilities/disposability` — модуль на машине не установлен; пустая выдача не доказывает отсутствие дубля.

Вход: базовый URL, каталог site/. Выход: строки «КРАСНОЕ: …», итог, код 0/1. Состояния нет.
Граница: лишние файлы на сервере не видны (листинга нет) — их убирает rsync --delete при выкладке.
Оракул: `--selftest` — устаревший файл, снятый X-Robots-Tag, открытый .git, пустая выборка → красное.
Живой подлог 2026-10-20: дописан байт в index.html на сервере → КРАСНОЕ, после повторной выкладки — 0 нарушений.

Вердикт одноразовости: ДА — stdlib, без состояния, переписывается с нуля; граница — HTTP и каталог site/.
