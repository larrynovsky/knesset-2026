### Ловушки

1. `ForOptionDesc` / `AgainstOptionDesc` определяют, **что означает «за»** в конкретном голосовании: принять · передать в комитет · отклонить. Без них голоса не интерпретируются (§10).
2. Кнессет **объединяет 2-е и 3-е чтения** в одно голосование.
3. **Три несовпадающих пространства ID персон**: `KNS_Person.Id` · vip_id (в `KNS_PlenumVoteResult.MkId`) · site id. Моста `Person.Id ↔ vip_id` в API **нет** — «как голосовал» и «что вносил» напрямую не соединяются. Мост vip_id ↔ site id даёт `KNS_MkSiteCode`. Проверено на двух персонах, не на всех 120.
4. HTML-страницы (`main.knesset.gov.il/*.aspx`) закрыты ботозащитой Reblaze — 247/474 неброузерным клиентам. API и статические PDF открыты.

# Фаза 0 — результаты разведки (2026-07-27)

Получено `scripts/probe_phase0.py` + `probe_phase0_odata.py`, запуск на Studio. Всё воспроизводимо.

## P0-1 · Бюджет: 1997–2025, и первоначальный бюджет ЕСТЬ

**Главное:** в таблице `budget` три раздельные величины, а не две.

| колонка | что это |
|---|---|
| `net_allocated` | **первоначально утверждённый** бюджет |
| `net_revised` | пересмотренный |
| `net_executed` | фактически исполненный |

§11 требует сравнивать факт с первоначально утверждённым — и это выполнимо. Те же три суффикса есть у `gross_*`, `dedicated_*`, `personnel_*`, `contractors_*`, `commitment_allowance_*`, `commitment_balance_*`.

**Глубина ряда: 1997–2025 с полным покрытием факта** (в каждом году `count(net_executed) == count(*)`). 2026 — 6 758 строк плана, факта нет.

⚠️ **Гранулярность плывёт и это ловушка сопоставимости.** Строк по годам: 2004 — 10 648 · 2012 — 10 160 · 2014 — 10 178 · 2017 — 2 595 · 2022 — 1 231 · 2025 — 2 282. Деньги не пропали — изменилась глубина публикуемой иерархии. Любое сравнение между годами требует нормализации по `depth` / `code_level2..8`, иначе «сокращение расходов» окажется сменой формата выгрузки. Прямая угроза §11.

`budget_changes` — 19 077 записей, 2005–2026. Это перебросы, в том числе коалиционные фонды. Отдельные таблицы: `raw_budget_2026_proposal` (предложение отдельно от утверждённого), `budgetary_change_requests_data`, `budgetary_change_transactions_data`.

## P0-3 · OData: голосования с 2003, фракции не сшиваются

### Формы запросов (иначе тихие 404/400)

- `/EntitySet/$count` → **404**. Работает только `?$count=true&$top=0`, значение в `@odata.count`.
- `KNS_PlenumVote` **не имеет поля KnessetNum** — режется по `VoteDateTime`; границы каденций из `KNS_KnessetDates` (165 записей — по сессиям, не по каденциям, границы надо агрегировать).
- ⚠️ **`$top=200` молча возвращает 100.** Страница жёстко сотня, без предупреждения. Обязателен обход `@odata.nextLink`.

### ⚠️ Фракции между каденциями не сшиваются НИКАК

Полная выборка 545 записей. **76 названий встречаются больше чем в одной каденции. Ни одно не сохраняет Id.** Идентификаторы выдаются заново каждую каденцию. Коллизий нет (один Id никогда не значит две разные партии) — но и преемственности нет.

| название | каденции | разных Id |
|---|---|---:|
| אגודת ישראל | 0,2,4–7,9–14,16,17 | 19 |
| מפלגה דתית לאומית | 3–9,11–16 | 13 |
| **הליכוד** | 8–16, 20, 23 | **11** |
| דגל התורה | 12,13,14,16,17,20–24 | 10 |
| ש"ס | 15, 20–24 | 6 |
| ישראל ביתנו | 15,16,19,20,24,25 | 6 |

**Хуже, чем «Id не сшивается»: не сшивается и название.** «הליכוד» под этим именем присутствует в каденциях 8–16, 20 и 23 — и отсутствует в 17, 18, 19, 21, 22, 24, 25, где Ликуд шёл в объединённых списках под другими названиями. То есть автоматической сшивки не существует ни по одному полю.

**Следствие:** `criteria/party_lineage.yaml` — не бухгалтерия, а несущая конструкция канала А. Без него межпериодное сравнение невозможно технически, а не только методологически.
