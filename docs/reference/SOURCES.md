### Ловушки

1. `ForOptionDesc` / `AgainstOptionDesc` определяют, **что означает «за»** в конкретном голосовании: принять · передать в комитет · отклонить. Без них голоса не интерпретируются (§10).
2. Кнессет **объединяет 2-е и 3-е чтения** в одно голосование.
3. **Три несовпадающих пространства ID персон**: `KNS_Person.Id` · vip_id (в `KNS_PlenumVoteResult.MkId`) · site id. Моста `Person.Id ↔ vip_id` в API **нет** — «как голосовал» и «что вносил» напрямую не соединяются. Мост vip_id ↔ site id даёт `KNS_MkSiteCode`. Проверено на двух персонах, не на всех 120.
4. HTML-страницы (`main.knesset.gov.il/*.aspx`) закрыты ботозащитой Reblaze — 247/474 неброузерным клиентам. API и статические PDF были доступны при проверке 27.07.2026; ограничение API по местоположению — п. 5.
5. **Геоблок API: HTTP 200 не означает JSON.** Проверено 07.10.2026 одним и тем же запросом `KNS_PlenumVote?$format=json&$count=true&$top=0&$filter=VoteDateTime ge 2022-11-15T00:00:00Z and VoteDateTime lt 2026-07-18T00:00:00Z` (пробелы и двоеточия кодируются в URL). На Studio — **200, `text/html`, 131 618 байт**, начало `<!DOCTYPE html>`, сообщение о недоступности из текущего местоположения на иврите, арабском, английском и русском. На MacBook — **200, JSON, 122 байта**, `@odata.count: 7535`. Класс ложного успеха по HTTP-коду тот же, что у легаси (§9). **Защита частичная:** `scripts/guarded_fetch.py::_get` отвергает HTML при `json.loads` с `JSONDecodeError`; отказ проверен подстановкой HTML. Отдельного распознавания геоблока и постоянной проверки этого случая нет.
6. **Состав прошлого окна может измениться.** Снимок `data/votes_25.json` на Studio от **31.07.2026** (`at: 2026-07-31T17:49:14.932255+00:00`) содержит `headers_total: 7540`; счётчик того же окна **07.10.2026 — 7535**. Границы: `VoteDateTime ge 2022-11-15T00:00:00Z and VoteDateTime lt 2026-07-18T00:00:00Z` (правая граница исключена). На пять записей меньше; счётчик не устанавливает их ID и не отличает удаление от изменения даты. **Защиты от изменения исторического состава нет:** `scripts/guarded_fetch.py::fetch_all` сверяет объём с текущим счётчиком, а не с прошлым снимком. Для §14 воспроизводим расчёт по сохранённому снимку при той же версии скриптов и окружения; побайтовое восстановление старого снимка через повторный запрос изменившегося источника не гарантируется. Это свойство источника, а не само по себе дефект расчёта. `Makefile::reproduce` перевыгружает только бюджет (`fetch-report`) и сравнивает две сборки на полученных данных, не с прежней публикацией; историческую воспроизводимость голосований он не проверяет. Без сохранённого снимка одного чистого клона недостаточно. Здесь ограничение **только записано**.
7. **Обрывы соединений на длинных сериях запросов.** Наблюдение 07.10.2026: один `http.client.RemoteDisconnected` на 994-м голосовании из 1809 запланированных при получении поимённых результатов; серия не повторялась для этой проверки. Оценка «один обрыв примерно на 500–1000 запросов» относится к этому наблюдению, не является частотой отказов: голосование требует нескольких запросов, точное число запросов до обрыва не зафиксировано. **Закрыто кодом частично:** `scripts/guarded_fetch.py::_get` повторяет обрыв (до четырёх попыток, затем `ShortRead`); его самопроверка подставляет обрывы и проверяет предел попыток. `scripts/fetch_votes.py::fetch_named_votes` сохраняет завершённые ответы отдельно в `data/named_votes_cache/<VoteID>.json` и повторно читает их. Сохранение уже полученных голосований реализовано, но отдельный оракул восстановления после прерывания здесь не подтверждён. Кэш содержит дату `at`; повторное чтение не сверяет его с источником, поэтому возобновлённая выгрузка может объединять разные даты снимков (`--no-vote-cache` отключает кэш).

### Четыре таблицы, и они не взаимозаменяемы

| таблица | что в ней | глубина | зачем |
|---|---|---|---|
| `raw_budget` | полное дерево | коды длиной 2 / 4 / 6 / 8 / **10** | **рабочая таблица канала Б**: длина 10 = תקנה תקציבית |
| `budget` | подмножество того же | `depth` ≤ 4; 2023 — 1 245 строк | почему подмножество — **не выяснено**; до ответа не использовать |
| `budget_items_data` | плоский срез | поле `level`, `amount_allocated/revised/used` | второй, независимый путь к той же величине |
| `supports_data` | תמיכות: кто получил | `budget_code` + `recipient_entity_name` + `amount_paid` | слой НИЖЕ бюджетной строки — адресность |

Три величины в одной строке:

| колонка | что это |
|---|---|
| `net_allocated` | **первоначально утверждённый** бюджет — база сравнения по §11 |
| `net_revised` | пересмотренный, после переносов внутри года |
| `net_executed` | фактически исполненный |

Те же три суффикса у `gross_*`, `dedicated_*`, `personnel_*`, `contractors_*`, `commitment_allowance_*`, `commitment_balance_*`. Поле `non_repeating` заполнено у всех строк — нативный ответ на «בבסיס התקציב» (в базе бюджета) против разового выделения.
