# Как собрать карточку партии

Рецепт для следующей партии. Написан по следу первой (ШАС, 30.07.2026), а не
по замыслу. Почему карточка устроена именно так — в
[`../explanation/budget_mapping.md`](../explanation/budget_mapping.md); что
проверяет валидатор — в [`../reference/card_schema.md`](../reference/card_schema.md).
Здесь только действия.

Всё выполняется на Studio: `export PATH=/opt/homebrew/bin:$PATH`.

## 1. Достаньте денежные пункты соглашения

```
python3 scripts/ocr_agreements.py            # если соглашение ещё не распознано
python3 scripts/map_commitments.py --party <ид>
```

Получите список пунктов с номерами строк. Отберите те, где названа сумма или
названа бюджетная статья. Остальные не берите: обязательство без денег этим
конвейером не проверяется.

## 2. Отберите три-пять пунктов и объявите отбор

Не размечайте всё сразу. Берите пункты, которые ломаются **по-разному**:
названный в соглашении код статьи, сумма без адреса, обязательство «в базе
бюджета», обязательство под несколько строк.

Оставшиеся перечислите поимённо в `coverage.not_analysed_lines` и напишите
в `coverage.why`, почему их не брали. Пустой `coverage` — нарушение: «данных
нет» тихо читается как «претензий нет».

## 3. Для каждого пункта найдите ветку, а не строку

```
python3 scripts/map_commitments.py --commitment <ид> --candidates
```

Поиск выдаёт подсказки по совпадению слов. **Он не принимает решение.** Язык
соглашения политический, бюджета — административный; совпадение слов здесь
не сигнал. Возьмите из подсказок восьмизначную ветку и дальше читайте её
глазами:

```
python3 -c "import json;r=json.load(open('data/budget_takanot.json'))['rows'];\
[print(x['code'],x['year'],x['title'],x['net_allocated'],x['net_executed']) \
 for x in r if x['code'].startswith('00220102') and len(x['code'])==10]"
```

Ветку читайте целиком и за все четыре года, включая год до соглашения.

## 4. Напишите вывод ссылками, а не числами

В `conclusion` числа не вписывайте. Ставьте ссылки — их подставит генератор:

| форма | значит |
|---|---|
| `{0022010213:2023:allocated}` | база строки за год |
| `{0022010213:2023:executed}` | исполнение |
| `{absent:מקוואות}` | слова нет ни в одном названии статьи |
| `{nocode:0022010203}` | статьи с таким кодом нет |

Вывод без единой ссылки валидатор отвергнет. Оценочные слова («выполнено»,
«нарушил») тоже: карточка сообщает, что стало с деньгами.

Проверьте `{absent:…}` руками до того, как записать: термин ищется в
названиях статей, и однокоренное совпадение считается совпадением. Для
«כנסת» их 31, и все про парламент.

## 5. Заполните обязательные поля

- `readings` — минимум два, и не оба ослабляющих. Ослабляющее, усиливающее,
  переформулирующее.
- `counter_search.searched_where` — список конкретных источников **с датами**.
  «Искал, не нашёл» без области поиска не принимается.
- `counter_search.outcome` — `found`, `nothing` или `contradictory`.
- `confidence` + `confidence_reason` — причина обязательна.
- `what_would_falsify` — чем именно ваше утверждение опровергается.
- `granularity` — из закрытого списка `criteria/budget_mapping.yaml`.
- `plan_year` и `fact_year` — один и тот же год.

`holdout_checked` оставьте пустым, если отложенный период не прогоняли. Тогда
`confidence: high` станет недоступен — так и должно быть.

## 6. Прогоните контракт

```
python3 scripts/validate_cards.py
```

Красное — читайте текст ошибки, там назван §. Зелёное означает, что поля на
месте, **не** что карточка осмысленна.

## 7. Запишите отпечаток и соберите отчёт

```
python3 scripts/build_report.py --stamp
python3 scripts/build_report.py
```

`--stamp` подтверждает, что выводы написаны против текущих чисел. Гоняйте его
только после того, как перечитали выводы, а не «чтобы прошло».

## Если сборка отказала

**«данные под выводами изменились»** — obudget переписал строку задним
числом. В stderr напечатаны текущие значения. Перечитайте выводы против них.
Вывод остаётся верным — поднимите `card_version`, добавьте запись в
`revisions` и прогоните `--stamp`. Не остаётся — правьте вывод, потом то же
самое.

**«ссылка на строку, которой нет в выгрузке»** — код или год опечатан, либо
выгрузка не покрывает год. Проверьте `data/MANIFEST.json`.

**«заявлено отсутствие, но оно есть»** — ваш `{absent:…}` неверен. Переберите
названия статей на этот термин и перепишите вывод.

**«управляющие символы направления»** — OCR положил в цитату символ
переупорядочивания. Возьмите цитату из PDF заново.

**«канал transfers не реализован»** — переносы записаны на восьмизначных
кодах, обязательства на десятизначных, сопоставление не решено. Ссылайтесь
на базу и исполнение; перенос упоминайте прозой, без ссылки.
