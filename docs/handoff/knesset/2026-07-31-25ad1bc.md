## 3. Explanation — решения этого этапа и почему

### Что сделано за этап (4 содержательных коммита)

`ac7fc29` K2d_v2 в код · `4566f80` группа G · `abe2bb5` сужение лексики G ·
`f5cf71d` B-20 и P6. Плюс `624ff09` — план.

### Три дефекта одного класса, и это главный вывод этапа

**Решение доехало до одного носителя из двух — трижды за двое суток.**

1. **Кодбук поправлен, код нет.** K2d_v2 заменил K2d 30.07 в 12:45; код,
   написанный в 09:01, исполнял отменённое правило полтора дня. Цена: 56
   ответов из 131 отвергнуто, 30 из них вопреки правилу. Отсев был
   ОТБИРАЮЩИМ — срабатывал тем чаще, чем больше норм перечислил вендор. На
   контрольной норме с известным ответом выбросил два верных «+1» и оставил
   единственный неверный «−1». Прибор предпочитал лаконичность правоте.
2. **Правило без пункта чек-листа.** K8 приняли 30.07, пункта не завели, а
   лексика переписи строится ПО ГРУППАМ чек-листа — значит предмет правила не
   попадал даже в перепись. В корпусе 851 акта кандидатов было ноль по сути.
   Вопрос, из-за которого ШАС вышла из правительства 22.07.2025, для документа
   не существовал.
3. **Перепись расширена, голосования не пересобраны.** Обнаружено 31.07
   вечером, не закрыто. См. ниже.

Общее: механизма распространения решения по носителям нет. Очевидный ответ —
реестр «правило → носитель» — **проверен и отвергнут**: дешёвая версия
(«правило упомянуто где-то вне кодбука») даёт для K8 три упоминания и была бы
ЗЕЛЁНОЙ на самом дефекте, потому что кодбук уходит модели целиком. Плюс
владельческий фильтр «аппарат дороже работы». Вместо реестра сделана точечная
проверка «раздел чек-листа ↔ группа лексики» в `scan_bills.py:selftest`.

### Открытый дефект: сшивка голосований теряет принятые законы

`fetch_votes.py` сшивает заголовок голосования с именем законопроекта через
словарь «нормализованное имя → акт», при совпадении имён побеждает первый
(`dict.setdefault`).

Кнессет **переименовывает** акт при принятии: `הצעת חוק X` → `חוק X`.
Заголовок голосования хранит имя на момент голосования. Итог: **77 из 258
прежних голосований (30%) отвалились**, все три акта — принятые законы. Один из
них, реформа вещания, входит в оракул отбора; оракул остался зелёным, потому
что проверяет ПЕРЕПИСЬ, а не сшивку.

Инверсия, которая делает это серьёзным: **сшивка слепа ровно на актах, которые
прошли**. Умерший в преддверии остаётся сшитым навсегда.

Найдено только по снимку файла, снятому за минуту до перезаписи. Без снимка
новые числа выглядят лучше прежних (144 акта против 119).

**Попутно, и оно крупнее:** 124 имени из 824 указывают на РАЗНЫЕ акты
(повторные внесения разными депутатами). **104 голосования из 258 (40%)** сшиты
по такому имени и приписаны тому акту, что оказался раньше в файле.

**Разведка проведена, якорь найден.** `ItemID` в шапке голосования указывает на
пункт повестки, не на билль; сущности `KNS_PlenumSessionItem` не существует.
Зато существует **`KNS_BillName`** — история имён акта с меткой стадии
(`בקריאה הראשונה` / `בקריאה השנייה והשלישית` / `לחוק שהתקבל`), 28 111 записей,
из них 2 864 «принятый закон». Старое имя покрывается историей у **3 из 3**
потерянных актов.

Предложено (владельцем НЕ подтверждено): сшивать из истории имён; неоднозначность
разрешать датой голосования против интервала действия имени, а не порядком в
файле; добавить проверку на немонотонность — новая сшивка не имеет права терять
пару (акт, голосование), бывшую в прошлом прогоне.

### Предсказания: два промаха названы вслух

Группа G заведена ПОСЛЕ появления данных — это нарушение §3, оплаченное
предсказанием, записанным до пересчёта.

- **P1 промахнулся.** Ждали 90–260 добавленных актов, вышло 369. В файле
  заранее было записано, что значит перелёт, и это исполнено буквально: голый
  `פטור` оказался канцелярской формулой (161 акт из 173 без носителя
  приписанного признака — НДС, арнонна, парковка). Плюс два омонима того же
  класса, что `המוסד`/`רבנות`: `ישיבות` — это «заседания» (18 из 18), `עדה`
  лежит внутри `ועדה` — «комитет» (24 из 45). После сужения 166 добавленных —
  внутри полосы, но **это не подтверждение P1**: полоса проверялась первым
  числом. Промах остаётся промахом.
- **P3 признан слабым**: формулировка допускала прочтение, при котором
  предсказание не могло провалиться.
- **P2, P4, P6 подтверждены.** P4 точно: с появлением G1 все три вендора дают
  −1 по пункту G1 на подложенной норме; до него двое ставили F3 («норма под
  конкретное лицо»), а Anthropic давал 0 и в доводе против сам называл K8.
  P6: 48 голосований по 39 актам группы G — опасение, что предмет K8 живёт
  только в постановлениях, снято.
- **P5 не проверен** — требует полного прогона (Ф28).

### Решение B-20: четыре ячейки, не суммируются

Ось теперь двумерна: институты (A–F) и равенство (G). Владелец выбрал
показывать 2 измерения × 2 колонки K9 = четыре ячейки на фракцию, рядом и без
суммирования.

**Неочевидное следствие, которое легко потерять:** общего направления фракции
больше НЕ СУЩЕСТВУЕТ, строка «направление партии» подлежит удалению. Оставить
её значит сделать четыре ячейки украшением при одном настоящем числе — том
самом суммарном балле, который запрещает §13.

Второе: пустая ячейка ≠ смешанная, и при четырёх ячейках пустых станет много.
Слить «нет записей» с «направление одностороннее» — повторить ошибку §7 в
четырёх местах вместо одного.

### Ловушки, на которых уже спотыкались

- **Слишком строгая проверка выглядит как качество.** Валидатор производит
  отсутствие; меньшая куча читается как чище. Оба крупных дефекта сидели там.
- **Оракул, написанный автором проверяемого, наследует его слепое пятно.**
  Оракул отбора (8 актов: суд, полиция, юрсоветник, вещание) не мог покраснеть
  на пропаже целой темы.
- **Зелёный контроль на неверном основании.** До `expect_items` контроль
  проверял только знак; верный знак ставился через неверный пункт чек-листа.
- **Искать существующее по ИМЕНИ, а не по данным.** В этой сессии написана
  одноразовая диагностика в `/tmp` при существующем `scripts/diag_rejects.py`,
  который делает ровно то же. Ошибка того же класса, что чинилась.
