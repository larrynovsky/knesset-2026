## Риски (Four-Part Risk Stories)
1. Публичный репозиторий → индексируется помимо `noindex` сайта → содержание карточек о названных партиях ищется по их именам → нарушен §16, и читатель получает оценку без рамки (карточка без read.html). Жертва — партии и доверие к документу.
2. URL сайта в истории → краулер приходит по ссылке с GitHub → сайт в выдаче (как разобрано в поправке §16 31.07) → «частная по сути» страница становится открытой.
3. Переписанная история → старые хеши в lessons/handoff → ссылки битые → будущая сессия не может проверить урок по коммиту (`verify-ancestor` падает). Жертва — следующая сессия.
4. Два remote (studio, github) → push в один забыт → зеркало отстаёт молча (класс §23: успех без полноты) → читатель GitHub видит старую версию. Lens consistency: single writer сохранён (MacBook), но копий две; лечится проверкой `ls-remote` обоих, а не дисциплиной.
5. Скан без показа выборки → «0 находок», потому что смотрел не туда (L005) → утечка уходит. Жертва — владелец (email, топология).
6. Лицензии источников не выяснены (CLAUDE.md, E) → данные Кнессета/BudgetKey в репозитории под лицензией проекта → правовая претензия. Данные `data/` не в git, но производные (`criteria/full_signs_*.json`, `vote_names_ru_*`) — в git.
