## Формулировка и критерий готовности
Глоссария нет (CLAUDE.md knesset раздела H не содержит). Уровень по смыслу — этап внутри проекта knesset. Роли: заказчик и получатель — Саша; исполнители — Claude (чтение, сборка) и Codex (независимые пересчёты); менеджер — Claude.

Сайт 19–20.10 собран «грубо»: знаки законов по темам поставлены по названиям (кроме экономики, перечитанной по полным текстам 20.10), часть решений (periods.yaml, правило «системно», линия Саара, нули по названию) отложена. Задача — не уточнять вслепую, а измерить, меняет ли уточнение то, что читатель видит на сайте; уточнять только там, где меняет. Затем выложить сайт на Hetzner.

Готово, когда: (1) у каждой темы и каждого фоллоуапа есть число «сколько выводов на сайте меняет уточнение» и цена получения, сведённые в одну таблицу-реестр; (2) по реестру Саша принял решения «уточнять / не уточнять», и принятые уточнения внесены; (3) сайт открывается с Hetzner по HTTPS, и внешняя проверка показывает: файлы побайтно равны site/ на Studio, noindex в заголовке и в каждом документе, служебные пути (.git, report/) не отдаются.

Валюта для всего — **изменённые выводы**, не изменённые знаки. Вывод: метка траектории (линия × тема, 19 линий × 4 темы = 76) и стрелка 25-го (фракция × тема, 16 × 4 = 64).

## Риски (Four-Part Risk Stories)
1. Пилот мал → интервал ошибки широк → «ошибка мала» принято по 0–1 из 20 → Саша вычёркивает по неверному выводу. Защита: пилот только опровергает; «стоп» лишь при годной модели Э1.
2. «Точный» оракул не независим от грубого: оба читателя — LLM, видят название внутри текста → общая ошибка не видна → D занижено → решение «не уточнять» на ложном основании. Защита частичная: два вендора; граница названа в реестре; ручной слепой проверки Саша не делает (его правило).
3. Сокращение N путается с исправлением → сдвиг меток от удаления выдаётся за эффект точности → неверная рекомендация. Защита: контроль случайного удаления той же мощности (control_must_be_powerful).
4. Выборка только из ненулевых → пропущенные законы невидимы → тема с 97 законами может терять треть вселенной → вывод по религии стоит на неполной выборке. Защита: Э4.
5. Push на Hetzner без обратной проверки → сборка на Studio упала (L010), а Hetzner отдаёт старое → друзья читают устаревшие выводы, никто не знает. Защита: штамп + hosted-check (pull).
6. rsync не того каталога или без белого списка → .git/report/data в вебкорне (WSTG-CONF-04) → внутренние разведочные страницы без рамки и noindex становятся публичными → доверие читателей и §16/§17. Защита: только site/, проверка 404 служебных путей.
7. HSTS с preload/длинным сроком при сбое сертификата → сайт недоступен браузерам, обход невозможен (WSTG-CONF-07) → за неделю до выборов. Защита: умеренный max-age, без preload, автопродление Caddy, проверка срока сертификата в hosted-check.
8. Ключ деплоя попадает в репозиторий → публичный репо (§18) → доступ к серверу. Защита: ключ в ~/.knesset_secrets, pre-commit скан §18.

## Стратегия тестирования (check vs test; кто смотрит)
Оракул эксперимента — второе прочтение по полному тексту двумя вендорами; он тоже ошибается (Bach: наличие оракула ≠ достаточный оракул). Поэтому:
- Проверки (check, машинные, с краснеющим мутантом): verdict_diff на подложенном изменении одной метки даёт ровно 1; нулевая выборка сравнения — отказ (L005); Codex-пересчёт D по сырым файлам без render_*; hosted-check с мутантами устаревшего файла и снятого заголовка.
- Тесты (test, человеческое суждение): чтение реестра Сашей — понятен ли ответ «уточнять или нет» без моих пояснений; /shining абзаца методики и реестра; открытие сайта с Hetzner в его Chrome рядом со Studio.
- Метрик покрытия нет. Отчёт — что проверено и что нет, числами.
- Кто смотрит: Саша — реестр и итог в чате; Claude — логи reviews/; Codex — отчёты REPORT_v9x.
